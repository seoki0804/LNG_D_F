# 한국 천연가스 수요예측: 용도별·지역별 1~12개월 앞 예측

수요예측 팀: 안형석, 양의창, 권기범

한국 천연가스 수요를 용도별(도시가스용·발전용)과 지역별(17개 시도)로 나눠, 수급계획에 필요한 1~12개월 앞을 예측한다. 회귀분석(강의 Ch1~8)으로 수요 구조를 추론하고, 통계 시계열·기계학습·파운데이션 모델을 같은 평가 절차로 비교한다. 같은 모델을 유럽 5개국에 적용한 비교 연구는 [`../multicountry/`](../multicountry/)에 있다.

## 결과 요약

1~12개월 앞 사전예측(미래 기온 = 평년값) MAPE(%), 평가 목표월 2023~2025년(모든 시계 36개월). 설정은 2020~2022년 검증 구간에서만 골랐다.

| 모델 | 도시가스용 | 발전용 | 합계 | 합계 (실제 기온) | 2026년 합계 |
| --- | --- | --- | --- | --- | --- |
| 계절 naive (기준) | 7.0 | 14.2 | 9.1 | 9.1 | 11.7 |
| 회귀 √Y | 5.4 | 10.9 | 6.5 | 5.2 | 11.6 |
| SARIMAX | 4.7 | 9.7 | 6.3 | 4.6 | 9.9 |
| LightGBM (직접 다기간) | 4.7 | 11.1 | 6.7 | 5.3 | 9.5 |
| 하이브리드 (회귀+Ridge) | 5.0 | 11.6 | 6.0 | 4.2 | 10.6 |
| Chronos-2 (공변량, 학습 없음) | 5.2 | 10.1 | 7.2 | 6.1 | 9.7 |
| TimesFM 2.5 (학습 없음) | 5.0 | 11.6 | 7.5 | 7.5 | 9.5 |
| 앙상블 (회귀·SARIMAX·LightGBM·Chronos-2) | **4.5** | **9.6** | **5.7** | **4.2** | 10.1 |

- **용도별로 난이도와 오차 원인이 다르다.** 도시가스용은 HDD로 변동의 98.5%가 설명되고, 오차의 약 38%는 기온 불확실성이다(앙상블 4.5% → 실제 기온 2.8%). 발전용은 기온으로 54%만 설명되고 기온을 알아도 오차가 11%만 준다. 발전용에는 원전·석탄 같은 공급 측 정보가 필요하다.
- **앙상블이 평균 1위지만 최고 모델은 하나가 아니다.** 1~12개월 평균 MCS(90%)에 12개 중 9~10개 모델이 남고, 발전용은 계절 naive까지 남는다. 2026년 표본 외에서는 합계 1위가 Chronos-2(단변량, 8.6%)로 바뀌었고, 2026년 7~8월 발전용 급증(각 약 192만 톤)은 모든 모델이 놓쳤다.
- **시도별 난방 민감도는 세 배 가까이 다르다.** HDD 10당 판매량 울산 1.0% ~ 제주 3.0%, 기울기 동일성 F = 96(p < 0.001). 2020년대에 17곳 중 15곳에서 커졌다.
- **계층 조정은 약한 모델만 개선한다.** 전국 MAPE: ETS 5.3% → MinT 5.0%, Chronos-2 5.1% → 4.7%. 전월 기온(검침 지연)을 넣은 회귀는 전국 직접 예측 4.7%가 최선이고 조정하면 나빠진다(MinT 5.7%).
- **회귀 추론:** 원 척도는 이분산(BP p < 0.001), Box-Cox λ 0.76 → √Y. 잔차 자기상관이 강해(DW 0.64) HAC 표준오차가 OLS의 1.7배. 2020~2025년 안에서 2022년 7월에 관계가 바뀐다(sup-F p < 0.001, 요금 인상기).
- **다른 나라와 비교(같은 모델):** 한국은 난방 민감도가 낮고(HDD 10당 1.5%), 1개월 앞 기준 회귀가 6개국 중 가장 정확했다(4.7%).
- 누수 점검 72건 모두 통과(`outputs/leakage_check.md`).

## 연구 질문

1. 도시가스용과 발전용 수요는 무엇으로 설명되는가? (기온, 요금, 전력수요, 석탄발전 상한제)
2. 시도마다 난방 민감도는 얼마나 다르고, 시간에 따라 변했는가?
3. 1~12개월 앞 예측에서 어떤 모델이 정확한가? 예측 시계가 길어지면 순위가 바뀌는가?
4. 기온을 미리 알면(완벽한 기온 예보) 오차가 얼마나 줄어드는가?
5. 지역별로 나눠 예측해 합치면(계층 예측) 전국 예측이 좋아지는가?

## 자료

| 자료 | 출처 | 기간 | 쓰임 |
| --- | --- | --- | --- |
| 용도별 월 공급량 (도시가스용·발전용, 톤) | [한국가스공사, 공공데이터포털 15129906](https://www.data.go.kr/data/15129906/fileData.do) | 2016-01~2026-09 | 전국 용도별 예측·회귀 |
| 지역본부별 용도별 공급량 (9개 지역본부) | [한국가스공사, 15049902](https://www.data.go.kr/data/15049902/fileData.do) | 2019-01~2026-09 | 전국 2019년 값 복원 |
| 시도별 도시가스 판매량 (17개 시도, 천㎥) | [한국가스공사, 15040819](https://www.data.go.kr/data/15040819/fileData.do) | 1989-01~2024-12 | 지역별 예측·회귀 (2022년까지) |
| 일평균기온 (시도 대표 관측소 25곳) | 기상청 ASOS 일자료 API | 1989-01~ | 시도·전국 HDD·CDD, 평년값 |
| 도시가스 소비자물가, 광공업생산지수 | KOSIS | 1989~ | 요금·산업 |
| 월별 전력거래량 | KOSIS (전력거래소) | 2001~2025 | 발전용 회귀 |
| 아시아 LNG 가격 | FRED PNGASJPUSDM | 1992~ | 발전용 회귀·예측 |

- **HDD·CDD**: Eurostat 방식(HDD = Σ(18 − Tm), Tm ≤ 15°C인 날; CDD = Σ(Tm − 21), Tm ≥ 24°C인 날). 넓은 도는 관측소 2~3곳 평균. 전국 HDD는 2016~2018년 시도별 도시가스 판매 비중으로 가중한 수요가중 HDD다.
- **평년 기온**: 직전 10년 같은 달 평균. 사전예측(실제 예측과 같은 조건)의 미래 기온으로 쓴다.

### 자료 점검에서 고친 것

| 문제 | 근거 | 조치 |
| --- | --- | --- |
| 전국 용도별 자료의 2019년 도시가스용 계절 형태가 어긋남 | 2019년 7월 1,750천 톤 (다른 해 약 900). 지역본부별 합계와 시도별 판매량의 2019년은 정상 형태 | 지역본부 합계 ÷ (지역본부 합계/전국 비율, 2020~2025 달별 평균)으로 복원 |
| 시도별 판매량이 2023년 1월부터 모든 시도에서 약 25% 낮아짐 | 같은 기간 전국 공급량은 그대로. 정의 변경으로 판단 | 시도별 분석은 2022년 12월까지 |
| 지역본부별 발전용이 전국 발전용의 1.2~1.8배, 2026년 7월부터 0.96배 | 정의가 기간 중 바뀜 | 지역 × 용도 교차 분석에 쓰지 않음 |

2019년 복원은 6개국 비교 연구(`multicountry/`)의 한국 자료에도 같은 방법으로 반영했다.

## 실행

```bash
# korea/ 에서
python python/fetch.py all            # 자료 수집 (기상청·KOSIS 키는 저장소 루트 .env, docs/API_KEYS.md)
python python/run_all.py              # 자료 가공 → 회귀(R) → 예측 → 평가 → 그림 → 보고서·발표 자료
python python/run_all.py --from evaluate
```

## 폴더 구조

```
python/
  config.py           경로, 시도별 관측소, 지역본부 구성
  fetch.py            한국가스공사·기상청·KOSIS·FRED 수집
  build.py            분석 데이터셋 (national.csv, province.csv), 2019년 복원, 수요가중 HDD
  mh.py               1~12개월 앞 롤링 평가 공통 코드 (미래 입력은 수요 열 없이 만든다)
  models_mh.py        계절 naive, 회귀 √Y, SARIMAX, ETS, Ridge·LightGBM(직접 다기간), 하이브리드(회귀+ML 잔차 보정)
  run_national.py     전국 용도별: 검증 구간 튜닝 → 평가 → 2026년 표본 외
  foundation_mh.py    Chronos-2·TimesFM 2.5 (학습 없음, 저장소 루트 .venv-fm)
  province_data.py    시도별 판매량 자료·기간
  run_province.py     시도별 계층 예측과 조정 (상향식·하향식·MinT)
  evaluate.py         앙상블, 예측 시계별 MAPE, DM 검정, 모델 신뢰집합(MCS), 기온 정보의 가치
  leakage_check.py    누수 점검 (예측 시점 이후 자료를 ×10으로 바꿔도 예측 불변)
  figures.py          논문 그림 8종 + 부록
  report_numbers.py   보고서·발표 자료의 수치를 report/numbers.json으로
  run_all.py          전체 실행 (자료 가공 → 회귀 → 예측 → 평가 → 그림 → 문서)
R/
  01_national_regression.R   용도별 회귀: 추론·진단·Box-Cox·동시추론·역예측·다중회귀·부분 F·구조변화
  02_province_panel.R        시도별 난방 민감도와 기울기 동일성 검정 (지시변수·상호작용)
outputs/                     결과 (national/, province/, regression/, figures/)
report/                      보고서·발표 자료 생성 (build_report.js, build_deck.js; 처음 한 번 npm install)
```
